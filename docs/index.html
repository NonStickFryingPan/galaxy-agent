Modern biology is a massive big data science.

PARADIGM SHIFTS

Every field has its eras.

Just like physics evolved from Classical Mechanics → Electromagnetism → Quantum, sequencing evolved in three generations:

  • 1st Gen (Sanger, 1970s–90s): Kilobases to Megabytes
  • 2nd Gen (Short-Read / NGS, 2000s–10s): Gigabytes (~60–100 GB per human genome)
  • 3rd Gen (Long-Read / ONT & PacBio, Present): 100 GB to 1.5 TB+ per run

We generate 3rd generation terabyte data, but students are stuck on 16 GB laptops.

Source: Logsdon, Vollger & Eichler, "Long-read human genome sequencing and its applications", Nature Reviews Genetics, 21(10):597–614 (2020). DOI: 10.1038/s41576-020-0254-8
Scientific fields advance through distinct paradigm shifts. Physics moved from classical mechanics to electromagnetism to quantum. Similarly, genomics has evolved through three generations: 1st generation Sanger sequencing took 13 years and dealt in megabytes. 2nd generation short-read NGS pushed us into gigabytes. Today, 3rd generation long-read sequencing—like Oxford Nanopore and PacBio—produces 100 GB to over 1.5 Terabytes from a single run. We have 3rd generation data, but students are still stuck on 16GB laptops.

HOW IT WILL WORK

How it will work

Just prefix whatever tool you want to run with gx- and it gets dispatched to the cloud:

Prefix with gx-
$ gx-bowtie2 -x hg38 -1 sample_R1.fq.gz -2 sample_R2.fq.gz -S sample.sam
$ gx-deepvariant --reads sample.bam --ref hg38 --output sample.vcf
$ gx-kraken2 --db Standard --paired read_1.fq.gz read_2.fq.gz
  • No new syntax to learn: Use the exact same parameters you already know.
  • Zero cluster scripting: gx- handles shipping the job and the remote environment.
The user experience is dead simple: you take whatever tool you want to run and prefix it with gx-. If you want to run Bowtie2, you run gx-bowtie2. If you want DeepVariant, you run gx-deepvariant. You use your normal tool flags, and gx- handles the execution on the cloud.
